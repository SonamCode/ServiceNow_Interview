### Question's Answer

## 1. Integration & API

**<a id="q1"></a>1. What type of integration have you worked?**
*   **Answer:** I have worked with both inbound and outbound integrations. Primarily, I have used REST and SOAP web services. I've integrated ServiceNow with third-party tools like Jira (for incident/issue sync), Workday (for HR onboarding), SolarWinds (for event management), and Active Directory (via LDAP/MID Server). I have also used IntegrationHub spokes for streamlined integrations.

**<a id="q2"></a>2. In REST what have you used?**
*   **Answer:** For outbound REST, I have used REST Messages, HTTP Methods (GET, POST, PUT, PATCH, DELETE), HTTP Headers, and Authentication profiles (Basic Auth, OAuth 2.0). I script the outbound calls using `sn_ws.RESTMessageV2`. For inbound REST, I have created Scripted REST APIs (with specific resources/endpoints) and used the standard Table API.

**<a id="q3"></a>3. Client needs one Knowledge Base API. API already returns KB details. Client also needs attachments. Need both in a single API. How to do it?**
*   **Answer:** You can achieve this by creating a Custom **Scripted REST API**. Inside the script resource, you first query the Knowledge (`kb_knowledge`) table to get the KB details. Then, you query the `sys_attachment` table where the `table_name` is 'kb_knowledge' and `table_sys_id` matches the KB article's sys_id. You can retrieve the attachment metadata and, if needed, the base64 encoded content of the attachment using `GlideSysAttachment().getContentBase64()`. Combine both the KB details and the attachment array into a single JSON object and return it.

## 2. Server-Side Questions / Scripting

**<a id="q4"></a>4. Scenario: User has a VIP flag (true/false). Once the user becomes VIP, automatically add them to a group.**
*   **Answer:** You can create an **After** or **Async** Business Rule on the User (`sys_user`) table.
    *   **Condition:** `VIP changes to true`
    *   **Script:** Query the `sys_user_grmember` table to check if the user is already in the target group. If not, insert a new record into `sys_user_grmember` mapping the `user` to the specific `group` sys_id.

**<a id="q5"></a>5. Which script to use to add in group?**
*   **Answer:** An After/Async Business Rule on the `sys_user` table. Inside the script, use `GlideRecord` on the `sys_user_grmember` table:
    ```javascript
    var grMember = new GlideRecord('sys_user_grmember');
    grMember.initialize();
    grMember.user = current.sys_id; // The VIP user
    grMember.group = 'SYS_ID_OF_THE_GROUP'; 
    grMember.insert();
    ```

**<a id="q6"></a>6. Fix Script vs Background Script**
*   **Answer:** 
    *   **Background Script:** Used by admins for quick, ad-hoc execution of server-side scripts. It is not captured in Update Sets, so it cannot be migrated between environments easily. Runs immediately.
    *   **Fix Script:** Designed to run server-side scripts that need to be migrated across environments. They **are** captured in Update Sets. They provide options to run in the background, run in the foreground, and allow you to test changes safely during deployments.

**<a id="q7"></a>7. We have 10 incidents and need to update from backend from In Progress to Complete. Don’t want to update system fields. Need to stop workflows/background logic. What are the 2 methods?**
*   **Answer:** You can use a Background Script or Fix Script with `GlideRecord`. To prevent system fields from updating and workflows from firing, use the following methods before calling `update()`:
    1.  `gr.autoSysFields(false);` // Disables updates to sys_updated_on, sys_updated_by, etc.
    2.  `gr.setWorkflow(false);` // Disables running Business Rules, Workflows, Flow Designer flows, etc.

## 3. Data Import & Transform Maps

**<a id="q8"></a>8. Concept of Transform Map scripts — onStart, onBefore, etc. What is the purpose?**
*   **Answer:** 
    *   **onStart:** Runs once before any rows are processed. Used to initialize variables or log the start of the import.
    *   **onBefore:** Runs before a row is transformed and inserted/updated in the target table. Used to validate or alter data for a specific row, or to ignore a row by setting `ignore = true;`.
    *   **onAfter:** Runs after a row has been inserted/updated. Used to perform actions that require the new record's sys_id (e.g., creating related records).
    *   **onComplete:** Runs once after all rows have been processed. Used for cleanup or sending summary notifications.

**<a id="q9"></a>9. I have one Excel with 10 records. During transform, how many times do scripts run?**
*   **Answer:** 
    *   **onStart:** Runs 1 time.
    *   **onBefore:** Runs 10 times (once for each record).
    *   **onAfter:** Runs 10 times (once for each record).
    *   **onComplete:** Runs 1 time.

## 4. CSM

**<a id="q10"></a>10. CSM – How do you manage account?**
*   **Answer:** In Customer Service Management (CSM), Accounts (`customer_account`) represent the external customers or business entities you support. You manage them by defining Account hierarchies (parent/child accounts), associating Contacts (`customer_contact`) to the accounts, assigning Account Teams (internal users managing the account), and defining Entitlements and Contracts specific to that account.

**<a id="q11"></a>11. In case of contract expiry, if they want to renew contract, how do you do that?**
*   **Answer:** In ServiceNow CSM/Contract Management, a contract can be renewed before or after expiration. You can use the **Renew** UI action on the Contract record. This typically creates a new contract record with a new start/end date, copying over the existing terms, rate cards, and associated assets/entitlements. The old contract's state moves to Expired, and the new one moves through Draft/Active states. We can also automate notifications (e.g., 30 days before expiration) using Flow Designer to alert the account manager.
