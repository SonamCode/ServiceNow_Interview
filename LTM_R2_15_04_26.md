## 2. Server-Side Questions / Scripting

**<a id="q4"></a>4. Scripting – how will you prevent a Business Rule from re-triggering?**
*   **Answer:** Inside the Business Rule script, before making a `current.update()` (which is generally discouraged in BRs anyway), I would use `current.setWorkflow(false);`. This function prevents any other Business Rules, workflows, or email notifications from running as a result of that specific update, effectively stopping infinite loops.

**<a id="q5"></a>5. Say I am using 2 conditions – After Insert or Async, where do you choose what?**
*   **Answer:** 
    *   **After:** I use this when the subsequent action must happen immediately, and the user or another system process relies on seeing the result in the exact same transaction before moving on.
    *   **Async:** I use this when the operation is heavy (like sending an outbound REST payload, processing many records, or calculating metrics) and I don't want to freeze the user's browser waiting for it to finish. It passes the task to the scheduler queue.

**<a id="q6"></a>6. (Image) Role selection for Script Include – what to choose?**
*   **Answer:** In a Client-Callable Script Include, you use the 'Role' field to restrict execution access. If it processes sensitive data, you assign a specific role. If it is meant for general ITIL users, you select `itil`. Leaving it blank allows any authenticated user to potentially call it, which is often against security best practices.

## 3. Client Scripts & Client-Server Communication

**<a id="q7"></a>7. I want to call server logic from Client Script?**
*   **Answer:** The best practice is to use `GlideAjax`. It allows the Client Script to make an asynchronous call to a server-side Script Include, execute the logic, and return a response without freezing the user's browser interface.

**<a id="q8"></a>8. Any shorter example of code?**
*   **Answer:**
    ```javascript
    // In Client Script
    var ga = new GlideAjax('MyUtil');
    ga.addParam('sysparm_name', 'getUserDept');
    ga.addParam('sysparm_userid', g_form.getValue('caller_id'));
    ga.getXMLAnswer(function(response) {
        g_form.setValue('department', response);
    });
    ```

**<a id="q9"></a>9. Populate all fields (Script Include form fields / GlideAjax configuration)**
*   **Answer:** If you need to populate multiple fields, your Script Include should fetch all necessary data, put it into a JavaScript object, and return it as a JSON string using `JSON.stringify(obj)`. On the client side, in the callback function, you use `JSON.parse(response)` to convert it back to an object, and then call `g_form.setValue()` for each key/value pair needed.

**<a id="q10"></a>10. (Image) Client Script form – explain / correct setup**
*   **Answer:** A proper Client Script requires selecting the correct target **Table**, setting the **UI Type** (Desktop, Mobile, or All), picking the trigger **Type** (onChange, onLoad, onSubmit), and checking the **Active** flag. Crucially, if it is an onChange script, you must explicitly define the **Field name** that acts as the trigger.

## 4. Integration & REST

**<a id="q11"></a>11. Can you explain any REST Message that you created? I want to call external API where I need to update the Incident**
*   **Answer:** I created an Outbound REST Message in ServiceNow to connect to a vendor's ticketing API. I configured an HTTP PUT method, set the API endpoint URL, configured OAuth 2.0 authentication, and defined variables like `${incident_number}`, `${state}`, and `${work_notes}` in the Request Body content.

**<a id="q12"></a>12. I want to update the incident – incident number I will take and update several fields**
*   **Answer:** I would set up an Async Business Rule on the Incident table triggered by the update. The BR would call a Script Include. The Script Include instantiates the REST Message (`sn_ws.RESTMessageV2`), replaces the variables with the actual Incident values (`current.number`, `current.state`), and executes the call to the external API.

**<a id="q13"></a>13. Not code, just explain in short**
*   **Answer:** 
    1. User updates Incident in ServiceNow.
    2. Async Business Rule triggers in the background.
    3. It gathers the updated incident data and constructs a JSON payload.
    4. ServiceNow sends an HTTP PUT request with the payload to the external API.
    5. The external system processes the JSON and updates their matching record.

**<a id="q14"></a>14. I want to see how you handle and write the code (JavaScript)**
*   **Answer:** I follow modular coding practices. I keep my Business Rules lean—they only contain logic to trigger the Script Include and pass `current` object parameters. Inside the Script Include, I use standard try-catch blocks for error handling, `sn_ws.RESTMessageV2` for the call, and `gs.error()` to log failures.

**<a id="q15"></a>15. Any shorter version?**
*   **Answer:**
    ```javascript
    try {
        var r = new sn_ws.RESTMessageV2('Vendor API', 'Update Incident');
        r.setStringParameterNoEscape('inc_num', current.number);
        r.setStringParameterNoEscape('state', current.state);
        var response = r.execute();
    } catch(ex) {
        gs.error("Integration failed: " + ex.message);
    }
    ```

**<a id="q16"></a>16. Explain line by line in short as well**
*   **Answer:**
    1. `try {`: Starts the error handling block.
    2. `var r = new sn_ws.RESTMessageV2...`: Instantiates the configured REST Message record.
    3. `r.setStringParameterNoEscape...`: Injects the current incident number into the REST payload variable.
    4. `r.setStringParameterNoEscape...`: Injects the current state into the REST payload variable.
    5. `var response = r.execute();`: Sends the actual HTTP request to the external server.
    6. `} catch(ex) { gs.error...`: If the network call fails, it catches the error and logs it in the system logs safely.
