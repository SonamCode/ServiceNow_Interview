## 2. Server-Side Questions / Scripting

**<a id="q2"></a>2. What is the difference between After and Async Business Rule?**
*   **Answer:** 
    *   **After:** Runs synchronously immediately after the database operation (insert/update) completes. The user has to wait for the script to finish before control is returned to the UI.
    *   **Async:** Runs asynchronously in the background. ServiceNow creates a scheduled job (`sys_trigger`) to run it when resources are available. Control is immediately returned to the user, making it ideal for performance-heavy tasks like external integrations or mass updates.

## 3. Integration & API

**<a id="q3"></a>3. One of the recent integrations you worked on?**
*   **Answer:** A recent integration involved connecting ServiceNow with Jira to synchronize incidents and issues. We used Outbound REST Messages with OAuth 2.0 for authentication. When a specific type of incident was created in ServiceNow, an Async Business Rule triggered a Script Include to send a POST request to Jira's API, creating a matching issue. The Jira ticket ID was then captured and updated back on the ServiceNow incident record.

**<a id="q4"></a>4. Any OAuth 2.0 authentication worked on? What techniques have you worked on?**
*   **Answer:** Yes, I have worked extensively with OAuth 2.0. Techniques involve setting up an Application Registry, defining the Client ID, Client Secret, Token URL, and Redirect URL. I've configured OAuth profiles in Outbound REST Messages, allowing ServiceNow to securely request and auto-refresh access tokens without hardcoding credentials in scripts.

**<a id="q5"></a>5. Main difference between Basic Authentication and OAuth?**
*   **Answer:** 
    *   **Basic Authentication:** Sends the username and password directly with every single API request (encoded in base64). It is less secure because if intercepted, the credentials are compromised.
    *   **OAuth 2.0:** Uses temporary, scoped Access Tokens instead of sending user credentials. It is much more secure because tokens can be easily revoked, have an expiration time, and restrict access to specific scopes without changing the underlying password.

## 4. Client Scripts / UI Policies

**<a id="q6"></a>6. When does onChange and onLoad run?**
*   **Answer:** 
    *   **onLoad:** Runs automatically when a form is first loaded and rendered in the browser, before the user interacts with it.
    *   **onChange:** Runs immediately when a user modifies the value of a specific field on the form and moves focus away from it.

**<a id="q7"></a>7. I have an onChange and I want it onLoad — can I run the same script?**
*   **Answer:** Yes. When you create an onChange Client Script, ServiceNow automatically includes an `if (isLoading) { return; }` block. This prevents the script from running on initial form load. If you want the script to execute both when the field changes *and* when the form initially loads, you simply remove or bypass that `isLoading` check.

## 5. Data Import & Transform Maps

**<a id="q8"></a>8. Transform Map Script?**
*   **Answer:** Transform Map scripts allow you to manipulate, validate, and alter data dynamically as it moves from the import set table (staging) to the target table. There are different types based on when they execute:
    *   **onStart:** Runs once before the import begins.
    *   **onBefore:** Runs before a specific row is inserted/updated.
    *   **onAfter:** Runs after a row is inserted/updated.
    *   **onComplete:** Runs once when the entire import is finished.

## 6. Catalog / Service Catalog

**<a id="q9"></a>9. You need to create a Catalog Item with one variable `requested_for`; if it’s from HR department, throw error / block HR users — how will you do it?**
*   **Answer:** The best approach to block them from being selected in the first place is to use a **Reference Qualifier** on the `requested_for` variable to filter out any users belonging to the HR department. Alternatively, you could use an onChange Client Script combined with GlideAjax to check the user's department and throw a `g_form.showFieldMsg()` or `g_form.clearValue()` if they are in HR, but a Reference Qualifier is cleaner and more secure.

**<a id="q10"></a>10. How to create the Catalog Item?**
*   **Answer:** Navigate to **Service Catalog > Catalog Definitions > Maintain Items**. Click the **New** button. Fill out the core details like the Item Name, assign it to a Catalog (e.g., Service Catalog) and a Category (e.g., Hardware), provide a Short Description, and finally click **Save** to make the related lists (like Variables) appear.

**<a id="q11"></a>11. (Catalog Item screen) — How to configure / fill the catalog item details?**
*   **Answer:** On the Catalog Item form, you configure the user-facing details and the backend process:
    *   **Basic Info:** Name, Short Description, and Description (rich text instructions for the user).
    *   **Location:** Select the 'Catalogs' and 'Category' where it should appear.
    *   **Portal Settings:** Attach a Picture/Icon and set Request Method (Order, Request).
    *   **Process Engine:** Define the Fulfillment process by attaching a Workflow, Flow Designer Flow, or Execution Plan.

**<a id="q12"></a>12. (Variable screen) — How to create the `requested_for` variable?**
*   **Answer:** From the Catalog Item, scroll down to the **Variables** related list and click **New**.
    *   Set the **Type** to `Reference`.
    *   Set the **Question** to "Requested For" and the **Name** to `requested_for`.
    *   Under the **Type Specifications** tab, set the **Reference** table to `User [sys_user]`.
    *   Check the **Mandatory** box if required, and click Submit.

**<a id="q13"></a>13. (Reference configuration screen) — How to configure `sys_user` / reference qualifier to block HR users?**
*   **Answer:** Open the `requested_for` variable and go to the **Type Specifications** tab.
    *   Set **Use reference qualifier** to `Advanced`.
    *   In the **Reference qual** field, enter an encoded query string that excludes the HR department. For example: `department.name!=HR` (if simple) or better, call a Script Include: `javascript: new MyUserFilter().getNonHRUsers();` where the Script Include returns a list of valid user sys_ids.
